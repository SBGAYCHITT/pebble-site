Widget 契约

一个 40 行就能写完的组件内核。同源、已注册、不远程加载脚本。

先看活的

下面三个都是走同一套契约挂上去的，源码在 public/widgets.js。

契约只有四个东西

1. 注册

PebbleWidgets.define('hello', {
  title: '打招呼',
  mount: function (root, ctx) {
    root.textContent = '你好，' + (ctx.config.who || '陌生人');
    return function () { /* 清理定时器之类的，可省略 */ };
  }
});

2. 挂载

页面上留一个带 data-widget 的容器就行。配置写在 data-config 上，是 JSON。

<div data-widget="hello" data-config='{"who":"小明"}'></div>

动态插入的节点调一次 PebbleWidgets.scan(容器) 就会补挂上，已经挂过的不会重复。

3. 上下文

  • ctx.config — 上面那段 JSON 解析出来的对象，解析失败就是 {}
  • ctx.root — 你的容器元素
  • ctx.on(evt, fn) — 订阅事件，返回取消订阅的函数
  • ctx.emit(evt, payload) — 发事件
  • ctx.setTheme(name) — 换强调色（teal / violet / amber）

4. 清理

mount 返回一个函数，卸载时会被调用。有 setInterval、fetch 回写的组件必须返回它，否则切页面之后定时器还在跑。

为什么不做远程加载

很多「插件化」方案会让运行时去拉一个 URL 执行。这个站在做的是分发 exe， 一旦允许任意脚本，任何一次供应链问题都会直接变成「下载页被人换了链接」。 所以这里的规矩是：组件必须跟着仓库一起发版，走 PR。

代价是社区不能自己上线组件，换来的是这里每一行 JS 都能在 git 历史里查到。

内置事件

  • mounted — { type, el }，某个组件挂上了
  • theme — 主题名，切色之后触发
  • version — 更新清单的原始对象（来自 /api/update/latest）

事件是进程内的，不跨标签页。要跨标签页用 BroadcastChannel，自己开。
